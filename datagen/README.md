# Parallel Data Generator for CloudEdgeBench

### Config
Edit `config.yml`


Supported patterns:
- uniform
- poisson
- zipfian
- burst
  - fraction
  - distribution

Supported data sources:
- `csv`
- `image_folder`

`image_folder` scans the configured directory recursively for `.png`, `.jpg`, and `.jpeg` files and publishes each frame as CSV in this format:
`id,width,height,data,timestamp`

For image frames:
- `id` is the file stem
- `timestamp` is generated by the existing pattern scheduler
- `width` and `height` come from the PNG or JPEG metadata
- `data` is the raw image file bytes encoded as `base64` or `hex`

### Patterns
If you would like to observe how generated data looks like, use the `patternTest.py` script. It generates `series.png` to visualize the generated data.
```
python3 patternTest_timeseries.py --host 127.0.0.1 --port 8080 --duration 10 --out series.png
```

### Run
Build the binaries with CMake:
```bash
cmake -S . -B build
cmake --build build --target datagen datagen_shared
```

For Kafka output in a local build, install librdkafka development headers before configuring CMake:
```bash
sudo apt-get update
sudo apt-get install -y librdkafka-dev
cmake -S . -B build -DDATAGEN_REQUIRE_KAFKA=ON
cmake --build build --target datagen datagen_shared
```

If CMake was already configured before `librdkafka-dev` was installed, remove the old build directory or configure a new one so `HAVE_RDKAFKA` is detected.

Two TCP implementations are available:

- `datagen`: the existing behavior from [`datagen_batch_new.cpp`](/home/ttekdogan/Desktop/nes/benchmark-framework/datagen/datagen_batch_new.cpp). Each TCP connection generates and sends its own stream independently.
- `datagen_shared`: the shared-stream behavior from [`datagen_batch_shared.cpp`](/home/ttekdogan/Desktop/nes/benchmark-framework/datagen/datagen_batch_shared.cpp). All TCP connections across all configured ports receive the exact same generated batches.

Switching between them is only a matter of which executable you run with the same config file:
```bash
./build/datagen config.yaml
```

```bash
./build/datagen_shared config.yaml
```

Use `datagen` if each client should have its own generator state. Use `datagen_shared` if one common generator should feed all connected clients in parallel with identical content.

### Slow Consumer Detection
Enable `slow_consumer` to flag clients that are not keeping up with the TCP stream:

```yaml
slow_consumer:
  enabled: true
  pending_socket_bytes_limit: 1048576
  write_duration_warn_ms: 100
  ack_timeout_ms: 0
  max_unacked_messages: 0
  log_interval_ms: 1000
  disconnect_on_slow: false
  sequence_header: false
  nonblocking_send: true
```

The transport-level checks use non-blocking sends, `SIOCOUTQ` pending socket bytes on Linux, per-write duration, and per-client pending write counters. When a threshold is exceeded, datagen logs `Slow consumer detected ...`; with `disconnect_on_slow: true`, it also drops that client.

Application-level ACK tracking is optional. Set `ack_timeout_ms` and/or `max_unacked_messages` to non-zero values, and set `sequence_header: true` if the client needs sequence numbers in the stream. The TCP payload is then prefixed with a line like `# datagen_seq=42`; clients can acknowledge by sending `ACK 42` or `datagen_ack=42` back on the same connection.

### Docker Deployment
The repository includes a self-contained Docker setup under [`docker/`](./docker).

Build and start the default TCP-based setup from the repository root:
```bash
docker compose -f docker/compose.yaml up --build
```

This will:
- build the `datagen` image
- mount `data/` into the container at `/app/data`
- mount [`docker/config.yaml`](./docker/config.yaml) as the active config
- publish ports `8080`, `8081`, and `8082`

To start the optional Mosquitto broker as well, use the MQTT profile and the MQTT-enabled config:
```bash
DATAGEN_CONFIG=/app/config/config.mqtt.yaml docker compose -f docker/compose.yaml --profile mqtt up --build
```

The Docker-specific configuration files are:
- [`docker/config.yaml`](./docker/config.yaml) for socket output only
- [`docker/config.mqtt.yaml`](./docker/config.mqtt.yaml) for socket output plus MQTT
- [`docker/config.kafka.yaml`](./docker/config.kafka.yaml) for socket output plus Kafka

To publish generated batches to Kafka, enable the optional `kafka` section:
```yaml
kafka:
  enabled: true
  brokers: "localhost:29092"
  topic: "bid"
  flush_timeout_ms: 10000
```

`brokers` is the librdkafka `bootstrap.servers` value. Use `localhost:29092` when a local `datagen` binary connects to the Docker Compose Kafka broker, and use `kafka:9092` when `datagen` runs inside the same Docker Compose network. `datagen_shared` also accepts optional extra librdkafka producer properties:
```yaml
kafka:
  enabled: true
  brokers: "kafka:9092"
  topic: "bid"
  properties:
    compression.type: "lz4"
```

To start the optional Kafka broker in Docker, use the Kafka profile and config:
```bash
DATAGEN_BIN=/usr/local/bin/datagen_shared DATAGEN_CONFIG=/app/config/config.kafka.yaml docker compose -f docker/compose.yaml --profile kafka up --build
```

For more detail, see [`docker/README.md`](./docker/README.md).
